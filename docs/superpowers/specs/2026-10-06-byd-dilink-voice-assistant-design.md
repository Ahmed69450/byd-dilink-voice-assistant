# مواصفات تصميم المساعد الصوتي لسيارات BYD DiLink
**تاريخ التصميم:** 2026-10-06  
**الحالة:** معتمد للتنفيذ  
**الهدف:** بناء مساعد صوتي ذكي غير معتمد على النماذج التوليدية الضخمة (No Heavy LLMs)، خفيف وسريع، يعمل بدون إنترنت للأوامر المحلية ويوفر قدرات محادثة ومعرفة عامة شبيهة بـ Amazon Alexa لنظام BYD DiLink المستند إلى Android.

## 2. المكونات والمسارات التفصيلية

### أ. معالجة الصوت (STT & TTS)
1. **التعرف على الصوت (STT - Speech-to-Text):**
   - استخدام مكتبة **Vosk Android SDK** بنموذج عربي مصغر وخفيف مدمج في أصول التطبيق (`assets/model-ar`).
   - الاستماع عبر نمط **Push-to-Talk** (زر واضح في الواجهة) لتوفير تجربة سريعة وآمنة أثناء القيادة.
2. **توليد الصوت (TTS - Text-to-Speech):**
   - استخدام محرك **Piper TTS** المحلي (أو واجهة `Android TextToSpeech` كبديل احتياطي فوري مدمج بالنظام) لنطق الردود باللغة العربية بطلاقة وسرعة ودون استهلاك للإنترنت.

---

### ب. محرك التوجيه اللغوي والذاكرة (NLU & FSM Memory)
يعمل محرك البايثون (`router.py`) على توجيه النصوص الواردة إلى أحد المسارات الثلاثة:

1. **معالجة النصوص (Normalization):**
   - إزالة علامات التشكيل وتوحيد الألف والياء والتاء المربوطة لتسهيل المطابقة.
2. **ذاكرة السياق متعدد الأدوار (FSM Memory):**
   - تخزين السياق النشط (`current_intent`) والكيانات المذكورة (`entities`) مثل المدن، درجات الحرارة، أو عناصر السيارة.
   - حل الضمائر وإشارات المكان: مثل ربط كلمة "هناك" بآخر مدينة تم السؤال عنها ("ما هو الطقس في القاهرة؟" -> "وما هو الوقت هناك؟").
   - دعم التعديل التتابعي لأوامر السيارة ("شغل التكييف" -> "خليه أبرد").
3. **تصنيف النية (Intent Classifier):**
   - فحص مرادفات اللهجات والفصحى وأفعال التحكم بالسيارة (`car_control`).
   - فحص أنماط السوالف والتحايا والأسئلة الشخصية للمساعد (`chitchat`).
   - توجيه الأسئلة العامة والاستعلامات الحسابية/الطقسية إلى المعرفة العامة (`general_knowledge`).

---

### ج. المسار A: أوامر السيارة المحلية (Branch A - Offline Car Controls)
- تنفيذ محلي 100% دون الحاجة لأي اتصال بالشبكة.
- يولد محرك البايثون كائن أمر منظم بصيغة JSON:
  ```json
  {
    "action": "SET_AC_TEMP",
    "params": {"temperature": 21, "unit": "celsius"},
    "spoken_feedback": "تم ضبط درجة حرارة التكييف على 21 درجة مئوية"
  }
  ```
- يتعامل `CarControlBridge.kt` مع أوامر BYD DiLink عبر:
  - **التكييف والنوافذ والإضاءة:** بث نوايا النظام أو التحكم بالواجهات المخصصة.
  - **الوسائط والصوتيات:** التحكم بـ `AudioManager` وأزرار الوسائط (`KEYCODE_MEDIA_PLAY_PAUSE`, `NEXT`, `PREVIOUS`).
  - **الملاحة والخرائط:** فتح خرائط النظام أو Google Maps بوجهة محددة عبر `ACTION_VIEW`.
  - **تطبيقات السيارة:** فتح تطبيقات DiLink (تطبيق الطاقة، الكاميرات 360، الإعدادات).

---

### د. المسار B: المعرفة العامة وحسابات أليكسا (Branch B - REST APIs)
عندما يكون النمط استعلامياً وعاماً، يتم استخدام عملاء REST APIs مع تلخيص الرد صوتياً:
1. **Wolfram Alpha Short Answer API:** للعمليات الرياضية المعقدة، والعلوم والتاريخ والحقائق الدقيقة (`v1/result`).
2. **DuckDuckGo Instant Answers API:** للتعريفات والمفاهيم العامة والشخصيات (`api.duckduckgo.com`).
3. **Open-Meteo API:** لحالة الطقس المباشرة والتوقعات لأي مدينة أو إحداثيات.
4. **NewsAPI:** لعناوين الأخبار اليومية العاجلة.
5. **World Time API:** لأوقات وتواريخ المدن والمناطق الزمنية.
- **الحماية عند غياب الشبكة (Offline Fallback):** في حال عدم توفر اتصال بالإنترنت في السيارة، يعتذر المساعد بلباقة ويذكر المستخدم بأن أوامر السيارة تعمل دون إنترنت.

---

### هـ. المسار C: السوالف والردود الودية (Branch C - Chitchat Persona)
- الاعتماد على قاعدة بيانات محلية غنية `chitchat.json` تحوي مئات الأزواج من الأسئلة والأجوبة باللغة العربية الفصحى واللهجات الشائعة.
- البحث والمطابقة باستخدام خوارزمية **Levenshtein Distance / Fuzzy Matching** لاختيار أفضل رد مطابق مع عتبة ملاءمة (Threshold).
- تضمين سكربت `fetch_kaggle_chitchat.py` لجلب وتنظيم مجموعات بيانات المحادثات العربية المفتوحة من **Kaggle**، مع تضمين بيانات افتراضية مسبقة ليعمل النظام فوراً.

## 3. حزمة أندرويد لـ BYD DiLink ومستودع Git
1. **حزمة التطبيق (Android APK):**
   - ملفات Gradle متكاملة تدعم Android SDK 28+ (المناسب لشاشات DiLink 3 و DiLink 4).
   - إعداد Chaquopy مع مكتبات Python المطلوبة (`requests`, `rapidfuzz` أو معالج المسافات المدمج).
   - أذونات Android الضرورية (تسجيل الصوت `RECORD_AUDIO`، استخدام الإنترنت `INTERNET`، وحالة الشبكة `ACCESS_NETWORK_STATE`).
2. **أداة الاختبار السريع (CLI Testing Tool):**
   - ملف `test_router_cli.py` لاختبار منطق التوجيه والذاكرة والـ APIs والردود مباشرة عبر موجه الأوامر قبل بناء الـ APK.
3. **التوثيق وإدارة الإصدارات (Git & GitHub):**
   - تهيئة مستودع Git محلي.
   - إنشاء ملف `.gitignore` احترافي يمنع رفع ملفات الـ build والبيئات الافتراضية.
   - كتابة `README.md` شامل بالعربية والإنجليزية يغطي التثبيت، وضع مفاتيح الـ APIs، وبناء الـ APK، وأوامر الرفع لـ GitHub.
